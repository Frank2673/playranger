# PlayRanger Demo Game — 预置 Bug 清单

本示例游戏预置了 3 个不同类型的 bug，用于测试 PlayRanger 的自动发现与复现能力。

---

## BUG-001: 状态重置不完整（HP 不重置）

- **类型**: 状态逻辑类
- **严重程度**: major
- **触发路径**:
  1. 点击「开始游戏」进入 Level 1（HP=100）
  2. 点击「下一关」进入 Level 2（HP 仍为 100）
  3. 用 set_param 把 HP 改成 50（模拟受伤）
  4. 点击 Level 2 的「重新开始」按钮
  5. **预期**: HP 应该重置为 100
  6. **实际**: HP 保持 50 不变
- **根因**: `level2-restart` 按钮的 onclick 处理函数里漏掉了 `state.hp = 100`
- **可复现性**: 100%（确定性）
- **验证断言**: `state.hp == 100` after restart

---

## BUG-002: 胜利页分数显示错误

- **类型**: UI 显示类
- **严重程度**: minor
- **触发路径**:
  1. 开始游戏 → 过 Level 1（score +100 = 100）
  2. 点 Level 2 的「通关」按钮（score +200 = 300）
  3. 进入胜利页面，查看「最终得分」
  4. **预期**: 显示 300
  5. **实际**: 显示 100（少了 200 分）
- **根因**: `renderUI()` 中胜利页分数计算用了 `state.score - 200`，应该直接用 `state.score`
- **可复现性**: 100%
- **验证断言**: 胜利页面 #win-score-text 包含 "300"

---

## BUG-003: 通关弹窗阻塞后续操作

- **类型**: 交互阻塞类
- **严重程度**: critical
- **触发路径**:
  1. 开始游戏 → 到 Level 2 → 点「通关」
  2. 页面弹出 alert("通关啦！")
  3. **预期**: 弹窗不应阻塞自动化流程，或有关闭机制
  4. **实际**: alert 是阻塞式弹窗，不手动点确定就无法继续
- **根因**: `level2-win` 按钮的 click 处理里调用了 `alert()`，阻塞了主线程
- **可复现性**: 100%
- **验证断言**: 页面存在未处理的 dialog / 后续点击操作超时
- **备注**: 这是自动化测试中常见的坑，用来验证 Agent 是否能正确处理 dialog

---

## 设计说明

三个 bug 分别覆盖不同维度：

| Bug | 类型 | 检测难度 | 需要的能力 |
|-----|------|---------|-----------|
| BUG-001 | 状态逻辑 | 低 | 状态追踪 + 断言 |
| BUG-002 | UI 显示 | 中 | 视觉检测 / DOM 检查 |
| BUG-003 | 交互阻塞 | 高 | dialog 处理 + 异常恢复 |

---

## 修复提示（开发测试用）

如果需要"修复版"游戏做对比，可以做以下修改：

- **BUG-001**: 在 `level2-restart` onclick 中加 `state.hp = 100;`
- **BUG-002**: 把 `state.score - 200` 改成 `state.score`
- **BUG-003**: 删掉或注释掉 alert 调用
