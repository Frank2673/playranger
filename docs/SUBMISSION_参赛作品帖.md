## 一、先说它解决什么痛点

3–5 人的独立游戏团队，通常**没有专职测试**：

- 每次改完代码靠自己手动点，覆盖不全，Bug 常常是玩家先发现；
- 想上自动化？GameDriver / AltTester 这类工具要**接 SDK、写测试脚本**，脚本还和版本强耦合，改版即失效；
- 玩家报"卡住了""分数不对"，**没有复现步骤、没有证据**，研发无从下手；
- 修完不敢发，怕修一个 Bug 又带出三个新的。

PlayRanger 把这件事反过来：**你不用写任何测试脚本**，只给一个游戏 URL 和一句目标（比如"通关第一关"），剩下的交给 AI Agent。

## 三、它会做什么（核心能力）

### 1. 零脚本自动试玩 —— 真的去"玩"，不是回放录屏

Agent 走的是 **ReAct 循环：读状态 → 想一步 → 走一步 → 验证对不对 → 不对就改**。配套**三层自修正**：

| 层 | 什么时候触发 | 怎么自救 |
|---|---|---|
| L1 动作层 | 点不到、参数非法 | 换定位、换参数重试 |
| L2 路径层 | 连续几步没推进 | 回退到上一个稳定局面，换条路走 |
| L3 策略层 | 整轮卡死 | 反思目标可达性，沉淀成一条"策略卡死"缺陷，不空转 |

每个动作执行前还有一道 **ActionValidator 硬校验**（白名单/前置条件/参数范围/枚举值），LLM 幻觉出的非法动作在落地前就被拦掉，不会把"AI 自己点错"误报成"游戏 Bug"。

两种模式同一套 Agent：
- **盲测模式**：游戏什么都不改，Playwright 抓 DOM + 截图给 VLM 判异常，适合第三方/已上线游戏；
- **SDK 精确模式**（可选）：游戏上报结构化状态（血量/分数/场景），直接对真值断言，精度到字段。

### 2. 证据可审计 —— AI 说有 Bug，凭什么信？

"是 AI 看错了吧？"——这是所有人对 AI 测试的第一反应。所以每个缺陷都带**多通道证据包**：

- 断言触发记录 + SDK 状态 / DOM / 截图 / 性能指标，多通道交叉验证；
- 完整**操作序列**（逐步 action + 当时的 hp/score/scene），按步骤可回放，支持种子的游戏可 100% 确定复现；
- 结论分三档：`auto_confirmed`（多通道一致，可直接进工单）/ `auto_warning`（单通道，建议复核）/ `human_required`；
- 证据链带 SHA-256 完整性校验，截图不能被偷偷替换。

### 3. 从"发现 Bug"到"怎么修" —— 不止步于报告

发现缺陷后，系统做**静态代码定位**（纯 AST/正则扫描，不依赖 LLM）：

- 按异常类型（遗漏重置 / 渲染偏移 / 渲染未绑定…）扫描源码，输出 `文件:行:列` 候选并排序；
- 对可识别模式直接生成 patch 草案；
- patch 在 `output/fix_sandbox/` **隔离副本**里 `git apply --check`，原始源码只读，绝不动你的工程；
- 给出根因、修复步骤、回归验证步骤、工作量与回归风险评级。

### 4. 平台化：并发、调度、持久化、鉴权

- FastAPI + SQLite 本地控制台，账号登录（Token 以 SHA-256 哈希入库）、任务归属；
- 按本机可用内存**自动建议并发 worker 数**（1–8 可手动扩缩，超建议值告警）；
- 任务状态机 `queued → running → completed / failed / cancelled / interrupted`，进程重启自动把遗留任务标记 interrupted，不会永久卡 running；
- 实时事件流、暂停/恢复/停止、失败重试、跨版本趋势差分（新增/修复/遗留）；
- CI 产物：JUnit XML / SARIF / Markdown，附 GitHub Action 与 Jenkins 库；
- **完全本地运行**：源码、截图、报告都不出本机。

## 四、真实数据：在第三方开源游戏 2048 上实测

我们没有只拿自制 Demo 自说自话。在**未修改的真实开源游戏 2048**（MIT 协议）上做了缺陷注入对照实验：往源码里注入真实缺陷，再让系统去发现、去定位。

### C 组：浏览器级 + 状态桥接 + 代码定位（5 个缺陷）

| 指标 | 结果 |
|---|---|
| 缺陷发现率 | **5 / 5（100%）** |
| 代码定位 Top-3 召回 | **4 / 5（80%）** |
| 可操作定位率（Top-3 命中或 patch 精确指向注入行） | **5 / 5（100%）** |
| 渲染类缺陷 patch 可直接应用 | 1 / 5 |
| 纯静态定位中位耗时 | **约 149 ms** |

| 注入缺陷 | 类别 | 严重度 | 发现 | 进 Top-3 |
|---|---|---|---|---|
| 重开后分数不归零 | 状态 | major | ✅ | ✅ |
| 合并计分少加（2+2 仅 +2） | 状态 | major | ✅ | ✅ |
| DOM 分数比真实值少 100 | UI | major | ✅ | ❌（patch 直接命中） |
| 合成 2048 不触发胜利 | 状态 | critical | ✅ | ✅ |
| 满盘仍可合并却判 Game Over | 状态 | critical | ✅ | ✅ |

### D 组：纯静态代码定位（10 个缺陷）

10/10 全部产出定位结果，其中 Top-3 命中 4/10、可应用 patch 2/10、可操作（Top-3 或 patch 指向行）6/10。

### B1 消融：零接入只看 DOM，能看出多少？

有人会问：不让读内部状态、只看用户能看到的界面呢？我们把证据通道砍到只剩纯 DOM，和干净版做对照——**带期望值时 5/5 都能与基线区分，但"零期望、只看一帧就知道是 Bug"只有 1/5**（那个缺陷会把分数显示成负数 −96）。其余像"分少加了""该赢没赢""不该结束却结束"，单看一帧界面无法判断对错，因为你不知道正确答案是什么。

这个结果诚实地划出了边界：**DOM 通道上限 5/5，但真正零 oracle 盲测远低于此**——这正是状态探针（高精度模式）和 LLM/VLM 语义复现（盲测模式）存在的理由。真盲测发现率（B2）我们还在测，不拿上限数字冒充。

**工程质量**：327 项自动化测试全部通过，含真实浏览器 E2E。

> **诚实边界（很重要）**：
> 1. C 组用了**固定种子垫片和只读状态探针**来保证可复现和拿到真值——这是实验夹具，不是产品能力；**盲测模式（纯 DOM + VLM）的发现率还没有量化数据**，我们不拿 C 组数字冒充盲测效果。
> 2. 代码定位目前只覆盖 3 类简单模式，跨文件调用链级别的缺陷定位不了；样本量是 5–10 个，不做统计显著性宣称。
> 3. 实验脚本和原始 JSON 全在仓库（`tools/run_2048_cgroup.py`、`output/experiments/2048/`），任何人都能一条命令复现。

## 五、三分钟跑起来

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 指定本机浏览器（也可 playwright install）
# Windows PowerShell:
$env:PLAYWRIGHT_CHROMIUM_PATH="C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"

# 3a. 启动正式控制台（首个注册账号自动成为管理员）
playranger server --port 8000
# 打开 http://127.0.0.1:8000/app/ ，新建任务填游戏 URL 即可

# 3b. 或直接启动「一键演示控制台」（自动播种 8 个历史任务/8 个缺陷）
python tools/demo_server.py
# 账号 demo / demo1234

# 现场复现 2048 C 组实验
python tools/run_2048_cgroup.py
```

也提供 CLI（`playranger test <url> --goal "..."`）、HTTP API（`/api/v1`）和 Python SDK。

## 六、和现有方案差在哪

| 维度 | 人工测试 | GameDriver / AltTester | modl.ai | Applitools | **PlayRanger** |
|---|---|---|---|---|---|
| 要不要接 SDK / 写脚本 | 不用，但要人肉 | 都要 | 要 | 不用脚本但只看视觉 | **盲测模式都不用** |
| 能发现玩法逻辑 Bug | ✅ | ✅（得写脚本） | ✅ | ❌ 只看像素 | **✅ Agent 自主探索** |
| 代码级定位 | ❌ | ❌ | ❌ | ❌ | **✅ 静态定位 + patch 草案** |
| 可复现操作序列 | 看运气 | ✅ | ✅ | ❌ | **✅ 全步骤记录 + 种子** |
| 可审计证据 | 主观描述 | 日志/截图 | 录像 | 像素 diff | **✅ 多通道交叉 + 完整性校验** |
| 私有化 | — | 企业版 | 云服务 | 企业版 | **✅ 完全本地** |

三条差异化主轴：**证据可审计**、**从结论到修法**、**零接入 + 私有化**。

## 七、我们很清楚它现在不行的地方

- **只支持 Web/HTML5 游戏**：手游、Unity/原生客户端暂不支持（已预留 `EngineAdapter` 协议和 AltTester 适配占位，但闭环未验证）；
- **盲测发现率未量化**：Canvas/WebGL 且无 DOM 状态的游戏，盲测只能靠截图 + VLM，成本高、精度低；
- **LLM 波动影响探索质量**：测试讲究可复现，而 LLM 有随机性。我们用动作硬校验 + 记忆 + 种子 + 确定性定位器来收敛，但这仍是核心待解问题；无 Key 时的 MockBrain 只保证流程能跑，不代表真实探索能力；
- **代码定位是轻量扫描**，不是跨过程数据流分析；
- 目前单机 SQLite 形态，没有多机分布式和团队 SSO。

这些都在仓库的 `SUBMISSION_功能说明与亮点不足.md` 里逐条如实记录，包括哪些已收敛、哪些没做。
